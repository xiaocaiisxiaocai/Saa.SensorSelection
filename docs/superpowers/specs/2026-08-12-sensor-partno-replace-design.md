# Sensor 料号 / 替换现用 / 停用搜索 设计

日期：2026-08-12

## 目标

- 现用型号、备选型号（及全部/停用）在状态列后增加可选 **料号**
- 备选型号可 **替换现用型号**，替换时必填 **问题点**
- 被替换的现用变为 **停用**；停用有独立 Tab，且页内/全局搜索可命中

## 方案

型号记录挂双向字段（方案 A），不建独立替换历史表。

## 数据

持久化仍为 `symtek_crud_store` → `sensor-catalog:all`。

`SensorItem` 扩展：

| 字段 | 说明 |
|------|------|
| `partNumber` | 可选料号字符串，空则不显示 |
| `replacesId` | 本型号作为现用时，替换掉的旧型号 id（可空） |
| `replacedById` | 本型号被停用时，接替它的新型号 id（可空） |
| `problemNote` | 问题点；替换双方写入同一文案 |
| `replacedAt` | 可选，替换发生的本地日期（便于停用列表展示） |

状态字典默认值：`现用`、`备选`、`停用`（写入 `sensor-status` 种子；已有本地字典若缺「停用」则在读取时补齐一次，不覆盖用户已改名的项）。

归一化：未知/缺失新字段按空处理；旧数据无料号/无替换关系仍可用。

## 替换规则

入口：仅在 **备选型号** Tab（或状态为备选的行）提供「替换现用」。

流程：

1. 选择目标现用（列表：同 `sensorType` 置顶，其余现用可选）
2. 必填问题点
3. 事务性更新（失败整单回滚）：
   - 备选 → `现用`，写 `replacesId = 旧id`、`problemNote`、`replacedAt`
   - 旧现用 → `停用`，写 `replacedById = 新id`、`problemNote`、`replacedAt`
4. 若旧现用原先也有 `replacesId`，保留其历史字段不主动清空（只保证「最近一次」双向指针正确）

校验：

- 候选必须是当前状态为「现用」且 id ≠ 自身
- 问题点 trim 后非空
- 存储失败回滚内存并提示

不在此版做：多次替换完整历史表、强制同类型、料号唯一。

## 界面

- 表格：状态后增加 **料号** 列（空显示 —）
- 编辑弹窗：料号可选输入
- 备选行操作：编辑 / **替换现用** / 删除
- 替换弹窗：目标现用下拉（同类型分组或置顶）+ 问题点多行输入
- 现用行：若有 `replacesId`，展示「替换了 {型号} · {问题点}」（可点跳转）
- 停用行：展示「被 {型号} 替换 · {问题点}」；停用 Tab 增加问题点列
- Tab：字典驱动，自动出现「停用型号」；顺序建议 现用 → 备选 → 停用 → 全部（SOP 仍最前）

## 搜索

- 页内搜索 haystack 增加：`partNumber`、`problemNote`、关联型号文本、状态「停用」
- 全局 `buildSearchIndex` 的 sensor `sub`/`title` 纳入料号与问题点，保证搜「停用」或料号可命中

## 回归

扩展 `pnpm run test:selection`：

- 料号可选保存与归一化
- 替换成功后状态与双向字段、问题点一致
- 缺问题点 / 目标非现用拒绝
- 搜索索引含停用与料号
