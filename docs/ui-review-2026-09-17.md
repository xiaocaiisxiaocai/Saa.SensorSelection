# UI / 交互全面检查报告

- 检查日期：2026-09-17
- 检查对象：`frontend/`（Vue 3 + 自建 Apple 规范组件库），对照 `frontend/docs/01-design-system.md`
- 检查方式：
  - 静态：`D:\Temp\ui-screenshots-2026-09-17` 全部 21 张截图 + 代码走查（tokens.css / AppShell.vue / `ui/A*.vue`）
  - 动态：Playwright 实机操作 —— 登录失败/成功、Tab 键序、弹窗焦点陷阱、Esc、删除确认、下拉键盘、分段控件键盘、表格行键盘、Toast、侧栏折叠、PDF/图片预览、报告生成、1440/1280/1024/900/768 五档宽度、浅色 + 深色模式

**整体结论**：视觉底子很好——令牌体系、材质模糊、发丝线、弹窗曲线、空状态、skip-link、`inert` 抽屉，这些都做到了较高水准。**问题几乎全部集中在"交互反馈"和"键盘可达性"上**：好看，但摸上去没有回应，且键盘用户走不通很多控件。

## P0 · 必须修（违反 Apple HIG 与自家设计文档）

### 1. 主按钮和所有下拉框完全没有焦点环

实测（键盘聚焦后读取 computed style）：

| 控件 | 焦点环 |
| --- | --- |
| `.a-button--filled`（每页主操作：新增型号/保存/筛选…） | ❌ 无 |
| `.a-button--plain`（取消/新建区域…） | ❌ 无 |
| `.a-select__trigger`（全部筛选下拉） | ❌ 无 |
| `.a-token-field__trigger` | ❌ 无 |
| `.a-icon-button` / `.a-segmented__tab` / `tbody tr` | ✅ 有 |

原因：`reset.css` 末尾的 `:focus-visible { box-shadow: var(--focus-ring) }` 与 `AButton.vue:110` 的 `.a-button--filled { box-shadow: var(--shadow-1) }` 特异度相同，组件 scoped 样式在后，直接把焦点环覆盖掉了。`--plain` 的 `inset 0 0 0 0.5px`（`AButton.vue:130`）同理。

违反 `01-design-system.md` §9「所有交互元素可 Tab 到达，焦点环统一」。

**修法**：在 `AButton.vue` 内显式写 `&:focus-visible { box-shadow: var(--focus-ring), var(--shadow-1); }`。主按钮上的焦点环建议带一圈底色间隙（Apple 标准做法），否则蓝环叠在蓝底上看不见：

```css
--focus-ring-offset: 0 0 0 2px var(--bg-content), 0 0 0 4px var(--sys-blue);
```

### 2. 下拉菜单（ASelect）完全无法用键盘选择

实测：Enter 能打开列表（4 个选项都在），但：

- 焦点留在 trigger 上（`focusInList: false`）
- 所有 `[role=option]` 都是 `tabindex="-1"`，且 `data-highlighted` 从未被设置
- ↑↓ / Home / End / 首字母跳转全部无响应
- Enter 直接关闭，值不变

即筛选下拉是纯鼠标控件。`01-design-system.md` §9 明确写了「菜单/下拉：↑↓ 移动、Enter 选中、Esc 关闭、输入字符跳转首字母匹配项」——一条都没实现。且 trigger 上既没有 `aria-activedescendant`，屏幕阅读器也读不出当前高亮项。

对比：`UserMenu` 用的菜单是正常的（Enter 开、↓ 移动、Esc 关并还原焦点），说明 Reka 的 Listbox 在 `ASelect.vue:126` 的接法有问题——多半是没把焦点移进 `ListboxRoot`。

### 3. 分段控件方向键：选中跳走了，焦点留在原地

实测（`ASegmentedControl.vue:56-67`）：

```
ArrowRight → 焦点="型号"  选中=SOP
ArrowRight → 焦点="型号"  选中=型录   ← 焦点和选中彻底脱节
Home / End → 无响应
```

处理器只改了 `model`，没有对新选中项调 `.focus()`，而 roving tabindex 已经把原元素改成 `-1`。Home/End 未实现。

### 4. 表格右侧有 400–800px 内容被藏起来，且几乎没有提示

Sensor 型号页（1440 宽）实测：内容宽 1652px / 可视 1250px，**402px 被裁**；1024 宽时**818px 被裁**。截图 `10-sensor-model.png` 里「适用场景」列被切成「投板测、」「气缸手臂」「狭小度定」——从汉字中间硬切，没有省略号——后面还有「关联型录」「关联 3D」两整列根本看不到。

`ATable.vue:447-459` 有 overflow 阴影，但：

- 渐变只有 8px（`--space-3`），且被不透明的 sticky「操作」列（`z-index:2`、`background: var(--bg-content)`）挡住
- `global.css:17-24` 把全局滚动条设成 `transparent`，只在 hover 时才显形——用户不移到表格上，根本不知道能横向滚

**建议**：

1. 列可见性菜单（Apple 的表格标配：右键表头选列）
2. 或把「特性与注意 / 适用场景」折进行展开详情
3. 滚动条至少在有溢出时常驻，或把边缘渐变加宽到 24–32px 并画在 sticky 列之上

### 5. 悬停反馈弱到看不见

实测 `--fill-3: 6%`、`--fill-4: 3%`，而设计文档写的是 12% / 8%。表格行 hover 从 `rgba(0,0,0,0)` → `rgba(116,116,128,0.03)`，白底上只有 4/255 的亮度变化，plain 按钮 hover 同样是 3%。

结果是整个应用摸上去"没反应"。这是 Apple 界面最讲究的部分（Finder/Mail 的列表 hover 非常明确）。把 `--fill-3/-4` 改回文档值 12%/8% 是投入产出比最高的一条。

## P1 · 重要问题

### 6. 登录页 Tab 第一站是右上角主题按钮

实测键序：`浅色 → 深色 → 跟随系统 → 用户名 → 密码 → 显示密码 → 登录 → 游客`。

- 违反 WCAG 2.4.3 / HIG 的「焦点顺序符合视觉顺序」
- 用户名框没有 autofocus（`document.activeElement === BODY`）——macOS 的登录窗口一定会聚焦第一个字段
- 三个主题按钮常驻工具栏，和文档 §10「在工具栏用户菜单里切换」不一致，白白占了顶栏

### 7. 表单错误"说两遍，还说得不一样"

弹窗里点保存（空表单）：

- 行内红字：`请输入要求内容`
- 顶部 Toast：`请填写要求内容并选择有效分类与来源`

两处措辞不同；且 2 个控件被标 invalid，却只有 1 条行内消息（分类/来源的错误只活在会消失的 Toast 里）。登录页也一样：行内 `请输入用户名` + Toast `请输入用户名和密码`。

Apple 做法：表单错误只在字段旁内联显示，不用 HUD。HUD 只用于"操作已完成/失败"这类瞬时结果。

### 8. 校验后焦点不移动 + 布局跳动

点保存失败后，焦点仍停在"保存"按钮上，键盘用户不知道哪个字段有问题（应移到第一个无效字段）。同时错误行出现后弹窗变高，保存按钮从 y=605 跳到 y=616；登录页更明显（553 → 575 → 564）。应为错误消息预留行高。

### 9. 登录失败后焦点丢到 `<body>`，密码被清空，屏幕上只剩错误的提示

实测失败后 `document.activeElement === BODY`，密码值被清空，残留在页面上的是「请输入密码」这个必填提示——真正的原因「用户名或密码错误」只在 4 秒的 Toast 里，一闪就没了。用户看到的持久信息是错的。

### 10. Toast 不可关闭，2.4 秒消失，而且压在全局搜索框上

`toast.ts:39`：普通 2400ms / 错误 4000ms；`AToastHost.vue:57` 固定在 `top: 8px` 居中——正好盖住顶栏的全局搜索框。没有关闭按钮，错误信息来不及读就没了。

**建议**：错误级 Toast 不自动消失 + 提供关闭按钮；位置改到右上角或右下角，避开工具栏。

### 11. 弹窗有输入内容时，Esc / 点遮罩静默丢弃

实测：填了字再按 Esc 或点遮罩，弹窗直接关闭，无任何确认。macOS 的编辑型 sheet 要么不响应遮罩点击，要么问「是否放弃更改」。

（弹窗其他方面做得很好：`role=dialog` + `aria-modal` + `aria-labelledby`、焦点陷阱 18 次 Tab 零泄漏、Esc 关闭后焦点正确回到触发按钮。）

### 12. 表格键盘操作只做了一半

实测：↑↓ 可以移动行焦点 ✅；Home / End 无响应，Enter 不触发主操作（文档 §9 承诺了「Enter 触发主操作」）。

### 13. 一个页面出现两个 filled 主按钮

操作日志页：`筛选` 和分页器的当前页码 `1` 都是 `a-button--filled`（实测）。违反文档原则 3「主按钮每个视图只出现一次」。分页当前页应该用 tinted 或选中态，不是主操作色。

### 14. 全表无排序

9 个表格 `sortControls` 全为 0。2685 条操作日志、117 个机型、Sensor 型录都不能按列排序。Finder / Mail / Numbers 的列表视图都是点表头排序——这是 Apple 表格的基本预期。

### 15. 两种 Tab 隐喻混用在同一层级

| 页面 | 一级切换 |
| --- | --- |
| 客户管理 / Sensor型号 / 数据字典 | 分段控件（胶囊） |
| 机型结构 | 下划线 Tab（`ATabBar`） |

机型页的「结构/专案机型」和客户页的「客户通用要求/制程注意事项…」是同一层级，却用了两套控件。HIG：分段控件用于同一数据集的视图切换，Tab 用于并列的内容区。建议统一为分段控件，机型页的二级「目录浏览/条件查找」保持分段即可。

配套 ARIA 问题：所有页面 `[role=tabpanel]` 数量为 0，`tablist` 没有 `aria-label`，`ATabBar.vue:145-154` 里 `role=tab` 和 `role=tablist` 之间还隔了一层 `div` 包装（破坏 ARIA 所有权关系）。

## P2 · 打磨项

### 16. 实现度量整体比自家文档"缩水"一档

| 令牌 | 文档 | 实际 | 备注 |
| --- | --- | --- | --- |
| `--sidebar-width` | 200px | 152px | |
| `--toolbar-height` | 60px | 52px | |
| `--row-height` | 40px | 36px | |
| `--control-height-md` | 32px | 30px | |
| `--control-height-sm` | 28px | 26px | 低于 Apple small 控件下限 |
| `--text-caption` | 13px | 12px | 文档明令 caption=13px |
| `--separator` | 29% | 16% | |
| `--fill-3 / -4` | 12% / 8% | 6% / 3% | 见 P0-5 |

小按钮 26px 高 + 12px 中文字，在 Windows 125% 缩放下偏挤。要么改文档、要么改实现，现在两边对不上，后续协作会持续跑偏。

### 17. `--label-3` 承载了信息（对比度 1.73:1）

`ASourceList.vue:665-670` 的分组计数（"华东 3"）用 `--label-3`，实测浅色 1.73:1、深色 2.48:1，远低于 4.5:1。文档 §9 自己写着「`--label-3` 只能用于占位符和禁用态，不能承载必要信息」。改用 `--label-2`。

侧栏分组标题 `.nav-group__label` 实测 4.43:1，差一点点，12px→13px 或提一档色即可。

> 其余文本对比度普遍很好（表格 21:1，深色模式 0 项不合格），这块整体是达标的。

### 18. 行高参差不齐

实测：客户页 114px / 48px；Sensor 页 92 / 92 / 92 / 92 / 70 / 70 / 92。长文本直接换行撑高。Apple 表格保持等高行 + 省略号，详情放展开行或检查器面板。现在的视觉观感是"锯齿状"的。

### 19. 空状态三套写法

| 位置 | 表现 |
| --- | --- |
| 机型页 | ✅ 完整 `AEmptyState`（图标 + 标题 + 说明 + 主按钮） |
| Sensor › SOP / 3D | ⚠️ 只有一行灰字「暂无 SOP 文件」，左对齐贴边 |
| Sensor › 型录 | ❌ 空的时候什么都不显示 |

违反文档原则 5「状态永远可见」。统一用 `AEmptyState`。

### 20. 列宽分配浪费

- 数据字典：`排序` 245px（放一位数字）、`字典项名称` 679px、`操作` 326px（放 2 个图标）
- 组织架构：`操作` 264px 放 3 个图标
- 而 Sensor 页却挤到要藏 402px

`ATable.vue:480` 的默认 `text-align: center` 也值得复议——Apple 的规范是文本左对齐、数字右对齐，居中只用于状态图标列。

### 21. 页面标题的处理不一致

选型类页面的 `<h1>`（客户管理 / 机型结构…）是 `visually-hidden`，屏幕上没有标题；系统管理类页面（用户管理 / 角色管理）有可见标题。且 DOM 里侧栏分组的 `<h2>` 排在 `<h1>` 前面，标题层级是倒的。

### 22. 其他细节

- 禁用的破坏性按钮仍是红色（`opacity:0.4` + `rgb(201,24,43)`），Apple 会转灰。不过 hover 提示「不能删除当前登录账号」做得很好
- 操作日志的「重置筛选」「上一页」禁用时没有任何解释（无 tooltip），对比用户管理页的做法不一致
- `ASourceList` 每一行都挂 tooltip（`ASourceList.vue:381,451`），即使文字没被截断也会弹——应只在 `scrollWidth > clientWidth` 时启用
- `ATabBar` 的重命名/删除图标 hover 时 opacity 仅 0.35（`ATabBar.vue:288`），且 `.a-tab-bar__actions` 在非 hover 时 `opacity:0` 又没有 `:focus-within` 兜底，键盘 Tab 到它时是隐形的
- 深色模式下 Tab 下划线用 `--sys-blue-solid`(#0066cc)，文字用 `--sys-blue`(#66b3ff)，同一个选中态两种蓝，视觉上下划线明显发暗
- 机型结构树标签截断过度：「01 入料输送（…」「02 入料输送（…」连续 8 条只能靠编号区分。面板可拖宽（有 `role=separator` ✅），但默认宽度应更大或改成两行显示
- 搜索结果行长度过长：单行跑满 1240px（100+ 汉字），建议限制到 60–75 字符宽；空分类（客户/制程/机型）不显示计数，应显示 0 或置灰
- 「登 录」按钮中间的空格会被屏幕阅读器读成两个词，建议用 `letter-spacing` 实现
- 弹窗里「适用机型」有占位符「如 ALL」，「适用制程」没有；「要求内容」是 3 行文本域而「备注」是单行输入，右列底部留空
