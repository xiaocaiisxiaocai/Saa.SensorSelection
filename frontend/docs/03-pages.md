# 03 · 信息架构与逐页规格

这份文档是**复刻清单**。表格列名、表单字段、校验、提示文案都是从现有代码逐条抄出来的，实施时当勾选表用。

## 1. 全局布局

```
┌──────────────────────────────────────────────────────────────┐
│ 工具栏 52px（材质 + 模糊）                                     │
│ [logo] 感应器选型     [全局搜索]                  [用户菜单]     │
├────────────┬─────────────────────────────────────────────────┤
│ 导航侧栏    │ 页面内容区                                       │
│ 260px      │                                                 │
│ （材质）    │ 部分页面自带第二级源列表（可调宽 220–520）         │
└────────────┴─────────────────────────────────────────────────┘
```

- 顶栏：`a-layout-header`，白底 + 底部 1px 分割线；左侧全局搜索（960px 以下前面多一个打开导航抽屉的按钮）、右侧用户菜单（`a-dropdown`）。
- 导航侧栏：暗色 `a-layout-sider` + `a-menu`（菜单项只有文字、不带图标；有多个分组时才显示分组标题「选型数据」「系统管理」，14px 加粗、白色实色（侧栏里只有分组标题加粗）、与品牌左对齐，组内菜单项再缩进 16px；只有一个分组时菜单项与品牌对齐），宽屏常驻 200px、不可折叠；960px 以下改为 `a-drawer`。
- 后端状态横幅（`a-alert`）在工具栏下方，仅 `offline` / `unauthorized` 时出现。
- **移除 Vben 的多标签页（tabbar）**。导航靠侧栏，不用浏览器式标签页。
- 客户页和机型页的左侧目录（`SourcePane` 包住 `EntitySource`）：右边缘可左右拖拽调宽（200–400px，方向键每次 16px，双击恢复默认：客户 240、机型 280），宽度按页面记在本机。目录树每层缩进 12px（`a-tree` 与 `a-tree-select` 下拉统一，见 `styles/global.css`）。1280px 以下改为上下排列：目录在上（客户约 32vh、机型约 40vh，机型的两排切换按钮并成一排），内容占满整行，不能拖拽。
- 所有表格和列表都不提供列排序，表头没有排序箭头。行序保持数据源原有顺序（仓库、领域层或后端默认顺序），导出跟随画面上的顺序。目录树的同级拖拽，以及字典、组织和 Tab 表单里的「排序」字段，不在这条限制里。

### 客户/制程（合并菜单）

客户和制程合并为侧边栏一个「客户/制程」菜单（`nav.ts` 的 `activePaths`：两个路由下都高亮）。父路由 `/selection`（`name: 'customer-process'`，`CustomerProcessPage.vue`，直接访问重定向到 `/selection/customer`）只声明两张 Tab，由通用组件 `shell/RouteTabs.vue` 在页面顶部渲染**卡片式** `a-tabs`「客户 | 制程」（组件自带样式，页面不写 CSS；以后别的菜单要合并多个子路由也用它），子路由仍是 `/selection/customer`、`/selection/process`，所以搜索结果、书签和 `?category=&item=` / `?tab=` 都不变。

- 卡片式 Tab 贴在下面的白色页面卡片上（选中 Tab 白底与卡片连成一体），与两个页面内部的线条式 Tab 区分层级。
- 每张 Tab 记住最后停留的完整地址：客户 → 制程 → 客户 回到原来选中的客户/区域，制程回到原来的子 Tab。
- 子页面渲染在当前 Tab 的 tabpanel 里；文档标题随子路由为「客户」/「制程」。

「系统管理」整组在无 `rbac:view` 时**不渲染**（不是禁用），沿用旧行为。

### 写权限门控

现有代码用 `v-can-write="'selection:write'"` 指令控制约 40 处按钮。新前端改为组合式：

```ts
const { canWrite } = useAccess()      // canWrite('selection:write')
```

规则（沿用旧语义）：**未登录可以只读预览全部业务数据**；无 `selection:write` 时所有新增 / 编辑 / 删除 / 上传 / 拖拽排序入口隐藏（不是禁用，与旧行为一致）。

## 2. 登录页 `/login`

- 居中 `a-card`（宽 400px），浅灰布局底色；`a-alert` 登录错误、竖排 `a-form`、游客入口用 `a-button type="link"`。
- 卡片顶部只显示系统名称「感应器选型」（20px 加粗居中，`aria-hidden`），**不放 logo**、不加副标题；另有一个读屏可见的 `h1.visually-hidden`「登录感应器选型系统」；版权信息在页脚。
- 表单：用户名（`a-input`，`maxlength=64`，`autocomplete="username"`）、密码（`a-input type="password"`，`autocomplete="current-password"`，回车提交）。
- 主按钮「登 录」（`filled` `xlarge` `block`，带 loading）。
- 底部「以游客身份预览（只读）」文字按钮：点击**清除残留 token** 后跳转。
- 已持有有效 token 时打开本页 → 直接跳业务首页，不显示表单。
- 支持 `?redirect=` 回跳，默认落到 `/selection/customer`。
- 提示：未填 → `toast.warning('请输入用户名和密码')`；失败 → `toast.error(后端消息)`；成功 → `toast.success('登录成功')`。

## 3. 客户（「客户/制程」的客户 Tab）`/selection/customer`

左侧 `EntityTree（a-tree）`（`groupLabel="客户"`、`itemLabel="区域"`：客户 → 区域，一个客户可有多个区域）+ 右侧详情。URL 同步 `?category=客户&item=区域`，定位同时匹配客户和区域（区域名会在不同客户下重复）；只给客户时落到该客户的第一个区域。四个 tab 的资料挂在区域上，数据名为 `客户/区域`。

切换客户时详情 tab 重置到第一个。无客户时右侧显示「暂无客户，请在左侧新建客户和区域」。改名当前选中的客户或区域后继续选中改名后的节点。

详情用 `a-tabs`，4 个 tab：

### 3.1 客户通用要求（`customer-req`）

工具栏：搜索框（占位「搜索分类、机型、制程、内容、来源或备注」）、重置、`新增要求`（主按钮）。要求分类和来源在对应列表头用漏斗筛选（多选，同一列命中任一即可，两列同时满足；未选表示全部）。

表格列：`要求分类` / `适用机型` / `适用制程` / `要求内容` / `来源` / `备注` / `操作`（编辑、删除图标按钮）。表头不排序，行序是仓库顺序。

弹窗「新增要求 / 编辑要求」（560px），两列网格：

| 字段 | 控件 | 必填 | 限制 |
| --- | --- | --- | --- |
| 要求分类 | `a-select`（字典 `customer-req`） | 是 | |
| 来源 | `a-select`（字典 `customer-req-source`） | 是 | |
| 适用机型 | `a-input` | 否 | 100，占位「如 ALL」 |
| 适用制程 | `a-input` | 否 | 100 |
| 要求内容 | `a-textarea` 3 行 | 是 | 600 |
| 备注 | `a-input` | 否 | 200 |

提示文案：校验失败「请填写要求内容并选择有效分类与来源」；`storage` 失败「数据保存失败，本次修改未保存」；`stale`「该要求已被其他页面删除」；成功「要求已新增 / 要求已更新 / 要求已删除」。删除确认标题「删除要求」，正文 `确认删除"{内容}"吗？`。

空状态：有筛选「没有匹配的要求记录」，否则「暂无要求记录」。

### 3.2 制程注意事项（`customer-proc`）

工具栏：搜索（「搜索分类、作用、特性、sensor注意或备注」）、重置、`新增`。制程分类在表头漏斗里多选，命中任一即可。

表格列：`制程分类` / `制程作用` / `制程特性` / `sensor使用注意事项` / `备注` / `操作`。

弹窗字段：制程分类（`a-select` 字典 `customer-proc`，必填）、制程作用（必填）、制程特性（必填）、sensor使用注意事项、备注。

### 3.3 感应器选用标准（受控文档）

按文件类型分区管理 PDF 与 Word 受控文档。

- 工具栏：搜索（「搜索文件名」）、上传入口（`a-upload-dragger`）。
- 上传限制来自 `CONTROLLED_FILE_RULES`：PDF 与 Word 各自的扩展名 / MIME / 大小上限，实施时从 `domain.js` 读取，不在 UI 里重复写死。
- 列表项：文件名、大小、上传时间、操作（预览 PDF、删除）。
- 预览用 `APdfViewer`（`a-modal` 承载），卸载调 `destroy()`。
- 校验失败提示：`size` → 文件大小超出限制；`type` → 文件类型不受支持。

### 3.4 厂外反馈问题项（`customer-feedback`）

工具栏：搜索（「搜索分类、机型、问题点、对策、时间或状态」）、重置、`新增`。问题分类和处理状态在对应列表头用漏斗筛选（多选，同一列命中任一即可，两列同时满足）。

表格列：`问题分类` / `适用机型` / `问题点` / `改善对策` / `反馈时间` / `处理状态`（`a-tag`）/ `操作`。

弹窗字段：问题分类（`a-select` 字典 `customer-feedback`，必填）、适用机型、反馈时间（`a-date-picker`）、处理状态（`a-select` 字典 `customer-feedback-status`，必填）、问题点（必填）、改善对策。

## 4. 制程（「客户/制程」的制程 Tab）`/selection/process`

无侧栏，整页 `a-tabs` 2 个 tab。URL 同步 `?tab=steps&q=`。

## 5. 机型结构 `/selection/machine`

最复杂的页面。左侧选单使用「分类 → 配置 → 机型」三层树；配置层可选，`专案机型` 等分类允许直接挂机型。分类、配置、机型编辑表单均提供 1 起算的排序字段，数组顺序即显示顺序。选单标题栏的新建按钮：结构目录是「新建分类」「新建配置」（默认放进当前选中节点所在的分类），机型从分类 / 配置行的「…」菜单里新建；专案机型没有配置层，标题栏是「新建分类」「新建机型」。右侧为一级 Tab（卡片式，右侧带报告工具栏）+ 选中节点的二级 Tab（线条式）+ 选中二级 Tab 的表格（示意图在表格「操作」前一列）。

**一级 Tab 共用，二级 Tab 属于选单节点**：一级 Tab 由当前目录（结构 / 专案机型各一套）共用，存在 `machine-tabs:all`，所有选单节点看到的是同一排。二级 Tab 属于「选单节点 × 一级 Tab」：点左侧某个节点，右侧只显示这个节点在当前一级 Tab 下的二级 Tab；每个二级 Tab 有自己的选型表和示意图（按二级 Tab 的 id 存放），格式由一级 Tab 的类型决定。二级 Tab 的名称在同一个一级 Tab、同一个节点内不重复。

**选单节点的下一层只能二选一**：
- 有子选单（分类下有配置或机型、配置下有机型）的节点不能有二级 Tab：选中它时右侧只提示「下有子选单，请在左侧选择下一级」，不显示一级 / 二级 Tab。这类分组 / 配置行点击只展开收起。
- 没有子选单的分类 / 配置可以选中，右侧显示一级 Tab 和它的二级 Tab。
- 机型（最末一层）**没有二级 Tab**：选中机型时右侧是一级 Tab，下面直接是这个机型的选型表（每个一级 Tab 一张，一级 Tab 徽标显示记录数）。表格在第一次新增记录时才建。删除机型时，表格有内容就不能删，空表格一起删掉。
- 节点有了二级 Tab 就不能再加子选单：它「…」菜单里的「新建配置」「新建机型」变成禁用的「新建…（已有二级 Tab）」；在新建 / 编辑机型弹窗里选到这样的位置会提示「所选位置已有二级 Tab，不能再添加机型」。
- 有二级 Tab 的节点不能删除，要先删掉它的二级 Tab。节点改名、机型换位置时，它的二级 Tab 跟着走。

URL 同步 `?category=&configuration=&item=&tab=&page=&focusRow=`（结构目录省略 `catalog`，专案机型带 `catalog=project`，条件查找带 `view=find`）；没有指定节点时选中当前目录的第一个机型，换节点时留在当前一级 Tab。机型数据不分「制程」：没有制程切换和「管理制程」（存储里没有 `machine-processes`，也没有 `@process:` 前缀的 key）。条件查找的版面见 §5.5。

### 5.1 报告工具栏

- 平时不显示勾选框。登录后（只读用户也可以）在「报告 ▾」里点「选择机型」，左侧选单每个节点和二级 Tab 上才出现勾选框，所有节点都能勾；点「完成选择」收起（已勾的保留）。勾一个节点 = 勾它下面的全部末级节点（机型，或没有子节点的分类 / 配置）：有二级 Tab 的勾它的全部二级 Tab，还没有二级 Tab 的单独记一个勾（报告里它是空的）；部分勾选时显示半选。两边状态同步。
- 文字：`已选 N / M`（按末级节点数：M 为当前目录的末级节点总数，N 为勾了的——有二级 Tab 的勾了任意一个就算），和一级 Tab 同一行靠右。
- 操作收在一个 `报告 ▾` 下拉里（给一级 Tab 让出位置，生成时按钮带 loading）：`选择机型 / 完成选择`（显示 / 收起勾选框）、`全选`（选上当前目录所有末级节点和二级 Tab）、`清空`（无选中时禁用）、分隔线、`生成并下载报告`、`预览 / 打印 PDF`（后两项无选中时禁用，菜单文字后缀「（请先勾选）」）。
- 报告每个一级 Tab 一节，节里按顺序列出所勾选二级 Tab 的内容，标题写成「节点名 / 二级 Tab 名」。
- 未勾选就点 → `toast.warning('请先勾选至少一个机型或二级 Tab')`；所选都没有内容（勾的机型还没有二级 Tab，或二级 Tab 里没有内容）→ `toast.warning('所选机型暂无可生成的内容')`。
- 生成成功 → 下载 `机型结构示意图报告-YYYY-MM-DD.html`，`toast.success('后端报告已生成并下载，可打开后打印为 PDF')`。
- 预览走 `window.open`，按当前屏幕的工作区原点与可用宽高铺满打开，可缩放、可滚动并自动聚焦；多屏环境不得按主屏坐标错位。被拦截 → `toast.warning('报告窗口被浏览器拦截，请允许弹窗后重试')`。

### 5.2 一级 Tab 与二级 Tab（一级 `a-tabs（editable-card）` + 二级 `a-tabs`）

当前目录一个 Tab 都没有时显示「还没有 Tab」引导空态和「新建 Tab」。一级 Tab 标题带徽标（选中机型时是它直属表格的记录数，选中分类 / 配置时是二级 Tab 数）；排序按 `sort`。右侧最上方（一级 Tab 之上）显示选中节点的完整路径（`a-breadcrumb`「分类 / 配置 / 机型」，最后一段加粗），因为左侧树里的选中项可能不在视野内。

- 选中的 Tab 显示编辑（改名 / 类型 / 排序）按钮，最右侧 `+` 新建（都需写权限）。Tab 上**没有关闭「×」**：删除 Tab 会连同所有节点在它下面的内容一起删掉，「×」容易被当成关闭页面，所以删除放在编辑弹窗里。
- Tab 弹窗（420px）：名称（`a-input` 40，必填，同一目录内不重名）、类型（结构 / 机型注意事项）、排序。Tab 下的二级 Tab 已有内容时不可切换类型。编辑时页脚左侧有红色「删除 Tab」。
- 删除一级 Tab：确认文案分开说明「N 个二级 Tab」和「N 个机型的选型表」会连同内容一起删除；删除成功后关闭编辑弹窗。
- 机型的直属表格为空时，空态写「「机型」在「Tab」下还没有选型记录（注意事项 Tab 为「注意事项」）」，有写权限时附「新增选型 / 新增事项」按钮。
- 二级 Tab 栏右侧「新建」（写权限）；选中节点在这个 Tab 下还没有二级 Tab 时显示空态「「节点」在「Tab」下还没有二级 Tab」和「新建二级 Tab」。新建弹窗（420px）只有名称（40，必填，同一 Tab、同一节点内不重名）。
- 每个二级 Tab 的「…」菜单（写权限）：改名、左移、右移（在同一节点的二级 Tab 之间，到头时禁用）、删除（确认后连同内容一起删除）。只读用户看不到「新建」和菜单。
- 旧数据：Tab 里原来记的是机型名（拖进去的机型）时，读出时转成同名的二级 Tab，挂在同名机型节点下，内容从机型的 1000 分区搬过去。

### 5.3 结构类 tab 的表格（`kind === 'structure'`）

## 6. Sensor 型号 `/selection/sensor`

顶部 `a-tabs`：`型号` + `SOP` + `型录` + `3D`。型号页里的状态是「状态」列表头漏斗，不是顶栏页签，也不是工具栏下拉。一个都没选就是分组的「全部」；选了任意状态（含三个全选）就是这些状态的扁平列表。`SOP` 是独立 PDF 文件库，不参与 Sensor 型号关联；型录沿用历史 `sop` 内部标识，避免破坏旧数据和旧链接。

`全部` 把型号收成组：每条现用后面先跟同 `sensorType` 的备选（仓库顺序），再跟沿着 `replacedById` 能走到这条现用的停用。停用按离现用最近的一代在前；同一代按 `replacedAt` 从新到旧，空日期排在这代最后，再按仓库顺序。备选和组内停用是弱化成员行（`sensor-row--alternate`）；组内停用另给正文删除线（`sensor-row--struck`，只包住文字，标签、按钮和合并格不加）。关联型录和关联 3D 合并成现用那一格，显示现用自己的链接。点组内空白不打开编辑；组内备选的「替换现用」锁定这一组的现用。没有同型现用的备选，以及替换链到不了现用的停用（没有 `replacedById`、指向不存在的 id、自环或成环），按仓库顺序单独排在末尾，样式与普通行相同，计入「共 N 条」。型号表和其他表格一样不提供列排序，避免打乱现用和备选的分组。

选中的状态是扁平列表：不分组、不弱化，每行自己的型录和 3D，整行可点编辑。多个状态按任一匹配。`停用时间` / `停用原因` 在选中的状态里包含停用时出现，分组的「全部」里不出现。

URL：默认「全部」不写 `tab`。只选一个状态时写入字典名（`?tab=现用`）。多选用逗号接起来（`?tab=现用,备选`，状态名本身不含逗号）。`?tab=全部` 会收成不带 `tab`。认不出的单个 `tab` 仍当作筛选，列表为空，不会退回分组。`?tab=sop-library`、`?tab=sop&sopId=`、`?tab=3d&model3dId=`、`?model=`、`?sensorTypes=漫反射,对照式` 仍可用。带 `?model=` 的深链接清掉状态筛选并填入搜索词；搜索框把同一个词写回地址栏时，不把当前状态筛选清掉。
